# 교육 신청 · 예약금 결제 설치 안내

홈페이지 신청서(`/apply/`) → Google Apps Script → 구글 시트에 저장되고,
토스페이먼츠로 과정당 예약금 30만원을 결제받는 구조입니다.

```
신청자 ─ 홈페이지 신청서 ─┬─▶ Apps Script(웹 앱) ─▶ 구글 시트 "신청" 탭 (한 과정 = 한 줄)
                          └─▶ 토스 결제창 ─▶ /apply/success/ ─▶ Apps Script가 토스에 결제 승인 요청 ─▶ 시트 "예약금 결제완료"
```

---

## 1. 구글 시트 만들기 (10분)

1. [sheets.new](https://sheets.new) 에서 새 시트를 만들고 이름을 `GARUDA 교육 신청 관리` 로 바꿉니다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 엽니다.
3. 기본으로 있는 `Code.gs` 내용을 모두 지우고, 이 폴더의 `Code.gs` 전체를 붙여넣은 뒤 저장(💾)합니다.
4. 왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성 → 속성 추가** 에서 아래 3개를 넣습니다.

   | 속성 | 값 |
   |---|---|
   | `ADMIN_EMAIL` | 신청·결제 알림을 받을 이메일 (여러 명이면 쉼표로) |
   | `DEPOSIT` | `300000` |
   | `TOSS_SECRET_KEY` | 토스페이먼츠 **시크릿 키** (3번 단계에서 발급, 처음엔 `test_gsk_…`) |

5. 편집기 위쪽 함수 목록에서 `setup` 을 고르고 **▶ 실행** → 권한 승인(“고급 → 안전하지 않은 페이지로 이동”은 내가 만든 스크립트라 정상).
   시트로 돌아가면 **신청** 탭과 **과정별 현황** 탭이 생기고, 상단에 **가루다 관리** 메뉴가 보입니다.

## 2. 웹 앱으로 배포 (5분)

1. Apps Script 편집기 오른쪽 위 **배포 → 새 배포**
2. 유형 선택 ⚙ → **웹 앱**
3. 설정
   - 설명: `GARUDA 신청 v1`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** → 나오는 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`) 을 복사해 전달해 주세요.
   → 홈페이지 `assets/data/config.js` 의 `applyEndpoint` 에 넣습니다.

> 코드를 고친 뒤에는 **배포 → 배포 관리 → ✏ 수정 → 버전: 새 버전 → 배포** 를 해야 반영됩니다. (URL은 그대로 유지)

## 3. 토스페이먼츠

### 지금 방식: 결제 링크 (적용됨)
`config.js` 의 `depositPayLink` 에 예약금 30만원 결제 링크가 들어가 있습니다.
- 신청서 한 장에 과정 하나. 신청 후 이 링크로 30만원을 결제합니다.
- 결제 결과가 홈페이지로 자동 전달되지 않으므로 **담당자가 확인**합니다:
  토스페이먼츠 상점관리자에서 결제 내역(이름·연락처) 확인 → 시트에서 그 행 선택 →
  메뉴 **가루다 관리 → 선택한 행 예약금 결제완료 처리** (결제상태 변경 + 신청자 확인 메일)
- 구글 시트 연결 전에는 신청 내용을 카카오톡으로 받습니다(신청서 화면이 안내).

### 나중에: 홈페이지 안에서 결제 (결제위젯, 선택)
결제가 끝나면 시트에 자동으로 '예약금 결제완료'가 찍히는 방식입니다.
`depositPayLink` 를 비우고 아래 키를 넣으면 전환됩니다.

1. [토스페이먼츠 개발자센터](https://developers.tosspayments.com) 로그인 → **API 키** 메뉴
2. **결제위젯 연동 키** 두 개를 확인합니다.
   - 클라이언트 키 `test_gck_…` → 홈페이지 `config.js` 의 `tossClientKey` (공개돼도 되는 키)
   - 시크릿 키 `test_gsk_…` → Apps Script 스크립트 속성 `TOSS_SECRET_KEY` (**절대 홈페이지에 넣지 않음**)
3. 테스트 키로 결제 흐름을 확인한 뒤, 계약·심사가 끝나면 `live_gck_…` / `live_gsk_…` 로 바꿉니다.

**실결제 심사 전에 홈페이지에 있어야 하는 것** (토스 심사 기준)
- 하단 사업자 정보: 상호, 대표자명, 사업자등록번호, 사업장 주소, 전화번호, 통신판매업 신고번호
- 환불(취소) 규정 — 예약금·잔금 각각의 환불 기준
- 판매 상품(교육과정)과 가격 안내 → `/programs/`, `/academy/` 에 있음

## 4. 관리자 사용법

**신청 탭** — 한 과정당 한 줄. 여러 과정을 한 번에 신청하면 같은 `신청번호` 로 여러 줄이 생깁니다.

| 결제상태 | 뜻 |
|---|---|
| 결제대기 | 신청서만 제출, 예약금 결제 전 (결제창을 닫았거나 진행 중) |
| 예약금 결제완료 | 토스 승인 완료 — **1영업일 이내 잔금 링크 발송 대상** |
| 결제실패 | 카드 거절·금액 불일치 등. `메모` 칸에 사유 |
| 취소 | 관리자가 직접 바꾸는 값 |

**잔금 링크 보내기**
1. 토스페이먼츠 상점관리자의 결제 링크(링크페이) 기능으로 잔금 금액 링크를 만듭니다. (`잔금` 칸 금액 참고, 계약에 링크페이가 포함되어 있는지 확인)
2. 신청 탭 `잔금 결제링크` 칸에 붙여넣습니다.
3. 해당 행들을 선택 → 메뉴 **가루다 관리 → 선택한 행에 잔금 링크 보내기**
   → 신청자에게 이메일 발송, `잔금상태`가 `링크 발송`, 시각 기록
4. 잔금이 들어오면 행 선택 → **가루다 관리 → 선택한 행 잔금 완납 처리**

※ 문자는 자동 발송되지 않습니다. `연락처` 칸을 보고 따로 보내 주세요.

**과정별 현황 탭** — 과정 × 교육시작일마다 결제상태별 인원이 자동 집계됩니다.
(예: Sling 2026-12-12 · 예약금 결제완료 3 · 결제대기 1)

**유입 분석** — `utm_source` / `utm_medium` / `utm_campaign` / `유입 페이지` 칸으로
어떤 광고가 신청으로 이어졌는지 필터·피벗으로 볼 수 있습니다.
광고 링크에 `?utm_source=instagram&utm_medium=paid&utm_campaign=barre_oct` 처럼 붙여 주세요.

## 5. 교육 시작일은 자동으로 맞춰집니다

신청서의 시작일 목록은 홈페이지 교육 일정(`assets/data/schedule.js`)을 그대로 읽습니다.
일정을 추가·변경하면 신청서에도 바로 반영되고, 이미 시작한 기수는 목록에서 빠집니다.
예정 기수가 없는 과정은 신청자가 희망 시작일을 직접 입력하며, 시트 `시작일 직접입력` 칸에 `Y` 가 표시됩니다.
